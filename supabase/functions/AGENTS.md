# Edge function rules

- Campaign ticks reuse handlers and pace globally start-to-start to avoid HTTP overhead.
- Meta health checks use a request deadline, bounded database/Graph reads and request-local token-scoped caching; incomplete reads preserve prior state and return per-instance errors instead of timing out the whole request.
- Template audits sync bounded manual batches before enqueueing; failed reads never mean missing templates, and only identified internal reservation failures may be recovered automatically.
- Daily Meta maintenance runs through meta-rotina-diaria, authorized only by its own cron token; it chains health, template sync/injection and webhook checks so internal callers keep service-role auth.
- SFTP UME/Odres daily sync (sftp-ume-auto, cron token 'sftp-ume-auto-*') downloads once to a private temp bucket because the SFTP server cannot seek, then UPSERTs in self-chained byte slices to stay under CPU limits; the final slice auto-applies payments matched to active agreements (CPF, value, due date) and keeps the history. Files too big to download within the function time limit (server is ~120 KB/s, no seek or parallel reads) can be posted via `?acao=enviar_arquivo` (admin or the SFTP_PONTE_TOKEN used by the daily GitHub Actions bridge) and run the same slice chain; already-processed files are skipped. Record 08 is payment date/paid value at columns 5–6 and installment due date/value at 9–10; matching uses the installment value and due date, and data_paga the real payment date.
- Campaign instance picks pass job_id so senders rotate by fewest sends in that campaign; YELLOW/RED stay below 30% of the healthy average, keeping BM quota and real blocks as filters.
- Portal agreements send the client confirmation through send-whatsapp-meta-text on their latest Inbox conversation; failures only flag the admin notice so the portal never breaks.
- The D-0/D-1 preventive reminder (UME/Novo Mundo/Odres, Utility-only senders) runs inside recuperacao-quebrados-auto's existing daily schedule as a separate campaign, so it adds no new cron and skips phones the recovery run already targets.
- Automatic Meta charge/reminder sends skip a CPF+creditor that already has a paid installment with the same due date or paid this month (_shared/parcela-ja-paga.ts), because duplicate agreements otherwise trigger charges to clients who paid.
- Every non-webhook function starts with `requireCaller` (_shared/auth-guard.ts): service role for internal calls, cron jobs send a scheduler Bearer token registered in their own active cron command, users need an app role; object-level checks use the caller's RLS (`asCaller`/`callerCanSeeRows`) so access never widens beyond the screens.
- UAZAPI webhooks must carry a registered instance token and always use the stored server URL; the Meta webhook verifies X-Hub-Signature-256 (observation mode until every sending app's secret is configured).
- The daily SFTP portfolio campaign (carteira-sftp-auto) runs inside process-campanha-meta-diaria's existing 08:00 BRT schedule, so it adds no cron; candidates come from one bounded RPC returning a single jsonb value (row results are capped by the API) with per-creditor fatigue, and go out as one job per creditor on disjoint sender sets so throughput doubles without two jobs competing for the same sender. Admin-requested same-day extra batches (`extra:true, credor, limite`) reuse the same candidate RPC and fatigue, so they never repeat recently contacted phones.
- First-installment recovery (D+1..D+3, one per day) runs inside recuperacao-quebrados-auto before the general overdue run and feeds its phones into that run's cooldown, so clients never get both templates on the same day.
- Proactive template sends pass a daily per-phone-suffix reservation (reservar_envio_diario_telefone, BRT day) inside send-whatsapp-meta-handler; test, manual Inbox, `proativo:false` (agreement confirmations) and manual campaigns whose creator chose to resend to recent contacts (`envio_meta_job.permitir_reenvio_recente`) bypass it, and Meta failures release it, so no client gets two campaign messages in one day.
- Replies to payment reminders get the owner's attendant tag, and that tag is locked, only in the PADRÃO box (null folder); custom boxes keep their own team's rotation so partner teams never inherit the owner's tag.
- UME propensity scores (ume_score_propensao, loaded from the creditor's classification sheet) give high-score CPFs top priority in the daily SFTP candidate RPC; the overdue recovery run always covers every installment overdue in the current month so the cushion (colchão) indicator is chased, while fatigue/blacklist filters still apply.
- The daily SFTP portfolio campaign sends half of each creditor limit at 08:00 and a dedicated 12:30 BRT cron (scheduler token) sends `complemento:true` to fill the rest, so daily volume stays the same while reaching clients at lunch.
- After an IAGO "Quero o boleto" PIX is sent, the existing follow-up tick sends one fixed check-in 2h later inside the open 24h window and then stops, so no paid template is used.
- The daily USA B2B prospecting run (usa-b2b-diario, own scheduler-token cron Mon–Sat 13:00 UTC = 08:00 Florida) captures new +1 business numbers into usa_b2b_leads, never re-contacts numbers from earlier USA jobs, and creates one Utility campaign into the USA B2B box; usa_b2b_config.ativo pauses it, and a same-day campaign already created (e.g. scheduled the evening before) makes the cron skip.
- The B2B COBRANÇA campaign (cobranca-b2b-campanha, admin-triggered, no cron) captures Brazilian collection agencies (mobile +55 only, suffix dedup) into cobranca_b2b_leads and creates one Utility campaign into the B2B COBRANÇA box, where IAGO sells mentoring/platform using _shared/vendas-cobranca.ts and books a demo instead of quoting prices.
- UME calls pick an account per operation (_shared/ume-conta.ts): the company account by default, and a partner's own UME account (UME_AMARAL_* secrets for Thiago's 'amaral' retailer) for that parceiro_meta user and for operators an admin assigns to his team (user_permissions.equipe_ume) in calculator/Inbox actions, plus IAGO on his numbers; fallbacks stay inside the same account so partners never use the company account and vice versa.
