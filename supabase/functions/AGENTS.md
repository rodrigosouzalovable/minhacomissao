# Edge function rules

- Campaign ticks reuse handlers and pace globally start-to-start to avoid HTTP overhead.
- Meta health checks use a request deadline, bounded database/Graph reads and request-local token-scoped caching; incomplete reads preserve prior state and return per-instance errors instead of timing out the whole request.
- Template audits sync bounded manual batches before enqueueing; failed reads never mean missing templates, and only identified internal reservation failures may be recovered automatically.
- Daily Meta maintenance runs through meta-rotina-diaria, authorized only by its own cron token; it chains health, template sync/injection and webhook checks so internal callers keep service-role auth.
- SFTP UME/Odres daily sync (sftp-ume-auto, cron token 'sftp-ume-auto-*') downloads once to a private temp bucket because the SFTP server cannot seek, then UPSERTs in self-chained byte slices to stay under CPU limits; the final slice auto-applies payments matched to active agreements (CPF, value, due date) and keeps the history. Files too big to download within the function time limit (server is ~120 KB/s, no seek or parallel reads) can be posted via `?acao=enviar_arquivo` (admin or the SFTP_PONTE_TOKEN used by the daily GitHub Actions bridge) and run the same slice chain; already-processed files are skipped. Record 08 is payment date/paid value at columns 5–6 and installment due date/value at 9–10; matching uses the installment value and due date, and data_paga the real payment date.
- Campaign instance picks pass job_id so senders rotate by fewest sends in that campaign; YELLOW/RED stay below 30% of the healthy average, keeping BM quota and real blocks as filters.
- Portal agreements send the client confirmation through send-whatsapp-meta-text on their latest Inbox conversation; failures only flag the admin notice so the portal never breaks.
- The D-1 preventive reminder (UME/Novo Mundo/Odres, Utility-only senders) runs inside recuperacao-quebrados-auto's existing daily schedule as a separate campaign, so it adds no new cron and skips phones the recovery run already targets.
- Automatic Meta charge/reminder sends skip a CPF+creditor that already has a paid installment with the same due date or paid this month (_shared/parcela-ja-paga.ts), because duplicate agreements otherwise trigger charges to clients who paid.
- Every non-webhook function starts with `requireCaller` (_shared/auth-guard.ts): service role for internal calls, cron jobs send a scheduler Bearer token registered in their own active cron command, users need an app role; object-level checks use the caller's RLS (`asCaller`/`callerCanSeeRows`) so access never widens beyond the screens.
- UAZAPI webhooks must carry a registered instance token and always use the stored server URL; the Meta webhook verifies X-Hub-Signature-256 (observation mode until every sending app's secret is configured).
